# 한 칸 더 — 전기자전거 탐구 노트

고1 융합동아리를 위한 **제작 안내 + 브라우저 활동 기록 + 거리 추정 실험 + 결과보고서** 사이트입니다.

- 사이트: https://alswl50978-eng.github.io/ebike-range-lab/
- 저장소: https://github.com/alswl50978-eng/ebike-range-lab
- 시작 상태: **제작 전**. 실제 활동·실험·성과를 만들어 넣지 않았습니다.

## 처음 시작하기

1. **따라 만드는 가이드**의 1단계부터 읽고 장비 정보를 확인합니다.
2. **거리 추정 실험실 → 가상 데이터로 연습**에서 입력 → 계산 → 출력 과정을 익힙니다. 가상 값은 실제 성능이 아닙니다.
3. 제품별 제조사 예제·핀·전원 사양을 확인한 뒤 실제 디스플레이 기본 출력을 시험합니다. 구체적인 드라이버가 미확정인 장비에 임의의 배선도를 적용하지 않습니다.
4. **나의 탐구 기록**에서 활동 글과 사진을 저장합니다. 이 웹사이트의 파일 선택 버튼으로 사진을 넣을 수 있습니다.
5. 실측 후 **실제 주행 기록**에 보정 자료와 별도 검증 자료를 입력합니다.
6. **결과보고서 → 이 기기의 초안 → 보고서 작성**에서 내용을 정리합니다.

## 계산 모델과 한계

같은 조건의 보정 자료만 사용합니다.

```
k = 주행 거리 합계(km) / 잔량 감소량 합계(%p)
추정 남은 거리(km) = 현재 잔량(%) × k
검증 구간 예상 거리(km) = 검증 구간 잔량 감소량(%p) × 당시 k
절대 상대 오차(%) = |예상 거리 − 실제 거리| / 실제 거리 × 100
```

잔량 변화가 없거나 증가한 기록은 보관하되 계산에서 제외합니다. 검증 자료는 보정에 섞지 않고, 검증 저장 시점의 계수를 고정합니다. 이는 %와 거리에 비례 관계가 있다는 가정을 검토하는 탐구 모델이며 실제 주행 가능 거리를 보장하지 않습니다. 가상 계수 `0.4km/%`는 설명용일 뿐입니다.

## 장비 범위

사용자가 제공한 팬텀 S2 및 배터리 정보, UNO, 3.5인치 TFT, ESP32-P4 디스플레이 보드의 정보를 사이트에 구분해 기록했습니다. 상품 상세 페이지는 열람하지 못했으므로 구체적인 LCD 드라이버·핀·개발보드 구성을 검증한 것으로 표현하지 않습니다.

이번 구현은 **수동 잔량 입력과 웹 LCD 시뮬레이션**입니다. 실물 하드웨어용 업로드 코드·자동 잔량 측정·무선 통신은 포함하지 않습니다. 제작 가이드의 의사코드는 제조사 예제를 확인한 뒤 계산 로직을 연결하기 위한 설명입니다. 자전거 배터리를 보드에 직접 연결하지 않습니다.

## 저장과 백업

- 글·사진·실험·보고서는 브라우저 IndexedDB에 저장됩니다. 같은 주소라도 다른 기기·브라우저의 초안은 서로 다릅니다.
- 활동 및 실측 입력은 **저장 버튼**으로 확정합니다. 보고서 편집과 단계 체크는 자동 저장합니다.
- 브라우저 데이터를 삭제하거나 시크릿 모드를 종료하면 초안이 사라질 수 있습니다. 한 탭에서 작업하고 **백업 · 공개 방법 → 전체 백업 내려받기**를 사용하세요.
- 백업 JSON에는 사진도 포함됩니다. **백업 파일 복원**은 형식을 검사한 뒤 기존 초안을 백업하고 대체합니다.
- 활동 사진: JPG/PNG/WebP, 활동당 6장, 장당 원본 15MB 이하. 긴 변 1,600px 이하 JPEG로 다시 인코딩하여 저장합니다. 원본 파일은 별도로 보관하세요.
- 복원 파일 한도 50MB, GitHub 웹 업로드용 공개 내보내기 한도 24MB. 큰 프로젝트는 사진 수를 줄이거나 활동별로 백업을 나누어 관리하세요.
- 사이트는 계정·분석 추적·외부 저장 API를 사용하지 않습니다. 파일 다운로드나 공개 파일 반영은 사용자가 직접 수행합니다.

## 공개 보고서 갱신

초안은 자동 공개되지 않습니다. 공개 사이트는 저장소의 `public-report.json`을 읽습니다.

1. 초안을 미리보고 공개하지 않을 이름·얼굴·정보를 정리합니다.
2. **공개용 파일 내보내기**로 `public-report.json`을 다운로드합니다.
3. 파일명이 `public-report (1).json`처럼 바뀌었다면 원래 이름으로 변경합니다.
4. GitHub 저장소 루트에서 **Add file → Upload files**로 같은 파일을 교체하고 커밋합니다.
5. Pages 배포가 완료된 뒤 사이트를 새로고침하여 **공개 보고서**를 확인합니다.

공개 저장소에는 변경 이력도 남습니다. 이 사이트에는 GitHub 토큰을 입력하거나 보관하는 기능이 없습니다.

## 인쇄 / PDF

결과보고서에서 **공개 보고서** 또는 **이 기기의 초안**을 선택한 뒤 **인쇄 / PDF 저장**을 누릅니다. 브라우저 인쇄창에서 PDF 저장을 선택합니다. 메뉴·편집 버튼은 인쇄에서 제외됩니다.

## 로컬 실행 및 테스트

런타임 의존성이 없는 HTML/CSS/JavaScript 사이트입니다. Node.js를 사용할 수 있다면:

```sh
npm ci
node tools/serve.cjs
node --test tests/*.test.cjs
```

`npm ci`는 DOM 테스트용 개발 의존성만 설치합니다. 배포된 웹사이트 실행에는 이 의존성이 필요하지 않습니다.

미리보기: http://127.0.0.1:4173/ebike-range-lab/

파일을 더블클릭하는 `file://` 방식 대신 HTTP 서버를 사용하세요. 공개 JSON 읽기와 브라우저 저장 동작을 일관되게 확인하기 위함입니다.

## 배포

GitHub Pages의 **Deploy from a branch → main → /(root)**를 사용합니다. `.nojekyll`로 정적 파일을 그대로 게시합니다. 별도 빌드, 비밀키, 서버는 필요하지 않습니다. 사용자 요청에 따라 GitHub Pages를 최종 호스팅으로 사용합니다.
